显示水印主要算法

```javascript
1、创建画布 
cosnt canvas = document.createElement('canvas');
2、创建 2d 绘图对象
const ctx = canvas.getContext('2d');
3、清理画布（通过将区域中的元素设置完全透明的黑色，达到擦除区域中元素的目的）
ctx.clearRect(0, 0, this.innerWidth / xCount, this.innerHeight / yCount);
4、填充画布的颜色和不透明度，设置字体和画布旋转角度
5、对要显示的水印文本进行处理
主要使用 ctx.measureText 测量要显示的字符串的长度，更具每一块画布的宽度进行切分，直到超过长度的水印的文字能分行显示完整；
6、使用 ctx.fillText() 填充文字
7、使用 canvas.toDataURL() 转化成base64 格式的图片，作为水印区域的背景
```

#### 5、组织架构树大量数据懒加载和批量加载
<!-- 主要技术要点：懒加载、逐级加载、滚动加载、只显示可视区域的树节点，需要和服务端约定好接口 -->
<!-- 预设每一个节点高度为 30px，视口高度是 300px， startIndex, endIndex -->
<!-- 节点数据结构
{
    name:'',
    nodeKey:'',
    id:'',
    parentId:'',
    childrens:[],
    z:'', // 层级用来显示缩进
    index: '', // 由前端生成用于
    idPath:[],
}
 -->
1、服务端返回组织结构树的一级节点，根据视口高度渲染，计算出能够渲染多少节点, 同时设置节点开始和结束索引位置
2、将服务端返回的节点数组，变成一层的的节点，为 treeNodes 并生成 index，和缩进；
3、滚动视口，得到滚动的高度 offsetTop，向上滚动多少，重新计算 开始的 startIndex,  offsetTop / 30, 加上视口的高度 clintHeight /  30， offsetTop / 30 + clintHeight / 30 为开始结束索引，从 treeNodes 获取展示节点，在视口中展示；
4、点击一级节点，服务端返回当前节点的子节点，遍历 treeNodes，打平数据，根据当前点击的节点，生成新的 z 和 index, 并且将之后的节点索引进行重新计算；
5、将重新整理后的子节点，在 treeNodes 中找到，当前点击的节点的索引，并插入其中，得到新的 treeNodes
6、重复第三个步骤，将页面渲染出来；

#### 10、大屏通过scale 进行适配
```javascript
function autoScale(selector, options) {
  // 获取大屏容器元素
  const el = document.querySelector(selector);
  // 设计稿上的宽度和高度
  const { width, height } = options;
  // 设置初始缩放比例和中心点
  el.style.transformOrigin = "top left";
  function init() {
    // innerWidth 屏幕实时缩放大小的宽度
    // innerHeight 屏幕实时缩放大小的高度
    const scaleX = innerWidth / width;
    const scaleY = innerHeight / height;
    // 取缩放比例小的值，保证大屏内容完整显示在容器内
    const scale = Math.min(scaleX, scaleY);
    // 计算偏移量，将大屏内容居中显示
    const left = (innerWidth - width * scale) / 2;
    const top = (innerHeight - height * scale) / 2;
    // 应用缩放和偏移量
    el.style.transform = `translate (${left}px, ${top}px) scale (${scale})`;
  }
  init();
  addEventListener("resize", init);
}
```

##### 对 echarts 图表提取出公共处理函数

项目中，主要运用 echarts 图表比较多。而且主要是折线图，柱状图和饼状图比较多，每次单独生成echarts 图表的时候，会写一套 生成配置的代码，然后调用 setOption 生成图表，重复代码太多，因此，提取公共的处理逻辑成统一的工具函数，根据不同图标的特征，约定统一的输入参数标准，然后返回 options 配置项
1、工具函数中公共部分，主要有，图例，颜色，toolTips，serises，x 轴的样式，数据分隔线等，y 轴的样式，数据分隔线等。
2、后续逐渐在图表定制化项目中，出现大量的相似图标，又对处理函数进行业务封装，根据业务封装单个的 echart 组件，在项目中开箱即用，只需要传入配置

   * 使用场景：工具函数中提供的基本定义的东西不能完全满足定制化的需求，但是，又有一些配置项是符合需求的，
   * 比如说，颜色，图标距离上下左右的边距，tooltip 的展示方式等不满足
