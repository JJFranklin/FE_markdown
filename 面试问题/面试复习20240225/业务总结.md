数据大屏适配问题

1、和产品确认好数据的来源和约束，根据展示空间的大小和服务器的性能来预判合理的数据量。
2、以柱状图为例，X轴的数据点如果太过于密集，就会缩小以至于重叠，需要让产品给出数据点的最小/大数量来判断需不要开启缩放拖拽等(这部分也会影响ui设计的版面大小和交互)。
3、Y轴的数据的来源是通过业务数据推算，还是手动控制，如果出现异常数据（极小值或者极大值）了之后需不需要过滤。还有一直比较极端的情况就是Y轴数据到达了千万以上级别（只是举个栗子），可能会出现数据被遮挡的情况，需不需要改用科学计数法（影响UI）

自适应分辨率
当用户的屏幕分辨率不符合我们的设计稿时，就需要动态适配。目前市面的解决方案有使用rem，transform缩放，vh/vw等。

1、使用 rem 的方式
动态修改根节点的fontSize值，然后通过px转rem的函数完成自适应；

```JavaScrip
setFontSize() {
   let designWidth = 1920 //设计稿的宽度
   let designHeight = 1080 //设计稿的高度
   // 这边是以宽度为优先级进行设置的
   const fontSize = (document.documentElement.clientWidth / designWidth) * 12
   document.querySelector('html').style.fontSize = fontSize + 'px'
 }

样式设置，提供一个公共的变换函数来对px 和rem 进行数据转换
@function px2rem($px) { 
    $design_font_size: 12; 
    @return ($px/$design_font_size) + rem;
}
```
最后的方案是 引入了 v-scale-screen 公共组件来适配

在此次项目中，主要负责，重点模块开发和技术方案的研讨，任务分配。
其中，做的比较好的，是在区域管理模块中，对于小区以及小区下属重点人员展示方式的优化，摒弃了传统的组织架构树的形式，改为更加直观的层级抽屉卡片模式。小区会以卡片的形式展示出来，卡片封面展示小区的图片和名称等信息，点击卡牌，卡牌右边可以展示所有下属的重点人员的图像，以及相关信息，并可以检索，优化了信息的显示。
第二个优化的点是，由于此次项目中需要的功能模块很多，结构比较相似，每次建立一个功能模块，需要手动添加响应的文件，很麻烦。
所以我搞了一个命令行的形式，npm run add-module:moduleName,
1、首先在文件下建立一套通用的模板，在结合json-template插件，对模板进行解析；
2、最后通过node 中的 fs（文件操作模块），生成指定目录，
3、写入之前，通过fs.exist 判断是否已经有了相同的模块，没有的话写入写入到指定的目录下。
4、最后通过 npm run addModule moduleName 来批量操作

这个批量操作在后来的项目推广使用，大大节约了开发时间。


第三个项目
陕西省西安市视侦算法采购项目

第三个项目比较特殊，是通过提取设备的唯一识别码，作为侦码，和收集到的人，脸，机，非数据进行关联。
比如说，在某一个布控了收集侦码设备的区域内使用过通信设别，就知道你是谁，然后对比分析底库中的相关数据，就知道了你的图像，进而能够得到你的在此活动区域内的全部公开信息，活动信息，会在地图上形成你的活动轨迹，甚至比对出和你一起出行人员的图像。
并且，通过我们的技战法分析，得到你是不是属于某一个团伙，是不是危险人员等警情信息
技战法分析：就是设定一些规则，比如说，在某个区域，多少天内连续出现多少次，累计出现时间长。在某个时间段内和谁同时出现的频率等信息，判断你是什么类型的人员。
在项目中运用了一键取色的功能，主要是使用 canvas 的 api，使用 drawImage 将图像信息填充到画布上，取色器点击，通过 getImageData 获取点击点的颜色，和底库做对比，得到相关信息。

第四个项目
江苏淮安涟水升级-昆仑
功能开发没有什么难点，难得是项目前期的准备，拆分功能点比较麻烦
将很久之前的项目进行系统升级并且更具甲方的需求加入新的功能
因为旧系统中只有少数的功能，新的系统本来有的有些功能点和旧系统功能点有些相似，又不能完全重用，而且加入得新的功能，是以新的系统为参照。
所以采取了一个最笨的办法，新旧系统对照分析，一个页面一个页面的过，相似的功能点一个一个列出来，完全是新功能点也列出来，感觉新系统中可以复用的功能点，单独列出来让需求方去和甲方沟通，尽量复用。
经过拆分比对，功列出了11个大类，39个功能模块，产出了很多中间记录的文件，也为后续的开发，提供了便利。
整理清楚了，开发起来其实很快，每个功能模块对应一个菜单，分配任务。
在开发中，发现，新的系统重每次添加新的菜单，需要服务端通过SQL进行操作，太麻烦，所以开发了一个菜单管理页面，专门添加删除菜单，后来发展成了一个简单的权限管理页面，可以控制角色的使用权限，页面上的功能等。

收获很大，开发功能不难，要整理好细节更加重要。理清楚了，开发就很快。
后来由于这个项目功能比较全，而且，在后面的定制化项目的开发过程中，有很多可以以这个项目进行二开，就逐渐把这个项目完善，在各大项目组中进行推广，最后推广落地了，取得了不错的效果。
